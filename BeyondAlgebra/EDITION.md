## v9.27 — 难度曲线撤掉拐点、改回全程指数 + 前期减压

**文件**：`密文轨迹demo9.27.html`（构建产物，源码在 `src/9x/`）
**基于**：v9.26

四块改动都挂在同一个数上：`getDifficultyMultiplier()`。

### 1. 曲线：撤掉 v9.15 的拐点与多项式尾巴

v9.15 给曲线加了拐点——30 层前 `1.16^(层-1)`，之后转多项式尾巴，理由是
「仍然一直变难，但不再涨成天文数字」（旧注释原话）。代价是**后期的「难」只活在
HUD 的数字里**：第 118 层难度系数被压到 ×662，怪的血量涨得却很有限，玩家感觉不到
差异。用户要的是「后期难度**指数**上升而非多项式」。

v9.27 把拐点和尾巴一起撤掉，改成**第 1 层起的单条指数曲线**：

```
v9.26   1.16^(层-1)                           （30 层后转 (层/30)^1.6 多项式尾巴）
v9.27   1.56^(层-1)                           （全程，无拐点）
```

底数从 1.16 抬到 1.56（绝对 +0.4，即 +40%）。`DIFF_TAIL` 整个删除。
`DIFF_KNEE = 30` 留着，但它**不再是难度曲线的拐点**——只当「前期 / 后期」的分界，
精华上限（`getEssenceCap`）与清层卡数（`getFloorClearCards`）还按它分档。

新曲线：1 层 ×1.00 → 10 层 ×54.7 → 20 层 ×4,671 → 30 层 ×3.99e5 → 50 层 ×2.90e9。

### 2. 三道「撞顶即封顶」的闸门一并抬走

那三道闸门是照旧曲线调的。新曲线会在半路撞上它们，**撞上之后怪不再变强、HUD 继续
涨**——这正是 v9.15 想避免的「假难度」，只是方向反过来。所以三道一起抬到只剩
「防溢出」的位置：

| 闸门 | 旧值 | 新曲线撞上于 | v9.27 |
|:--|--:|--:|:--|
| 怪物攻击（`diff^0.35` 的乘数） | ×12 | 第 17 层 | `ATK_OVERFLOW_GUARD = 1e9`（第 124 层） |
| 普通怪 HP | 1e9 | 第 37 层 | `HP_OVERFLOW_GUARD = 1e15`（第 68 层） |
| BOSS HP | 1e8 | 第 44 层 | 同一个 `HP_OVERFLOW_GUARD`（第 80 层） |

### 3. 前期减压

**普通怪**：新增 `EARLY_NORMAL_MUL = 0.7`，只在 `< DIFF_KNEE (30)` 层生效，且只打在
**普通怪**身上——精英与 BOSS 都不吃。与既有的 `MONSTER_STAT_MUL = 0.8` 叠乘
（0.8 × 0.7 = 0.56）。HP 与攻击都乘，移速不动。

**BOSS**：前期减压系数起点从 `BOSS_EARLY_MUL_START = 0.5` 压到 `0.35`——第 1 层正好
−30%，越往后衰减越少，第 20 层归零，20 层之后一点没动。

### 4. 显示：难度系数改走 `formatDiff()`

`1.56^(层-1)` 到第 100 层是 1.3e19，原来的 `toFixed(2)` 会印出二十几位数字把侧栏撑破。
新增 `formatDiff(v)`：`< 1e4` 走两位小数、`< 1e6` 走千分位、再往上走 `e` 记数法。
HUD（`diffDisplay`）、结算界面、模拟报告三处都改走它。

**故意保留两处 `+getDifficultyMultiplier().toFixed(2)`**：`snapshotStats()` 的
`difficulty` 与 `10-sim.js` 的 `finalDifficulty` 是给分析管线读的 **number**，不是给人
看的字符串——前面那个一元 `+` 就是「转回数字」的意思。探针把这条写成了断言：
全项目这样的数值字段**恰好 2 个**，任何显示路径都不许出现它。

## v9.26 — 摇杆失灵的真正成因 + 教程重排与字幕节奏

**文件**：`密文轨迹demo9.26.html`（构建产物，源码在 `src/9x/`）
**基于**：v9.25

只动了两块：手机端输入、新手教程。但第一块是**第三次**修同一个报障，前两次都没修到根上。

### 1. 「选完层数之后摇杆不动」的真正成因

v9.24 把摇杆的 `touchstart` 从 `#gameCanvas` 挪到 `.canvas-wrap`（铺满全屏那层），
v9.25 又把左半屏判定从 canvas 坐标改成屏幕坐标——**两次改的都是「按在哪」，可报障
说的是「选完路之后」**，这两件事根本无关，所以两次都是白改。

成因在 `pointer-events` 的优先级上：

```
styles.css:37   .canvas-wrap                  { pointer-events: none }
styles.css:49   #gameCanvas                   { pointer-events: none }
styles.css:724  body.mobile .canvas-wrap      { pointer-events: auto }   ← 手机端靠这条活着
```

节点地图是画在 canvas 上、靠鼠标事件选点的，所以 `showNodeMap()` 打开时会把 canvas
**和它的父层 `.canvas-wrap` 一起**设成 `auto`；`selectNode()` 选完关掉时又一起设回
`none`。**inline style 盖过 styles.css**——手机端那条 `body.mobile .canvas-wrap
{ pointer-events: auto }` 从此失效，而摇杆的监听恰好就挂在 `.canvas-wrap` 上。

于是：**玩家第一次选完路，整块战斗界面就永久收不到触摸**，只在下次打开节点地图时
「活」一下。问题从来不是监听挂在哪个元素上，是那个元素被设成了 `pointer-events: none`。

修法是把两层收敛到**唯一入口** `setCanvasPointer(want)`（`03-tutorial.js`），
**手机端永不写 `.canvas-wrap`**：

```js
function setCanvasPointer(want) {
    canvas.style.pointerEvents = want ? 'auto' : 'none';
    if (!G.mobileMode && canvas.parentElement) {     // ← 桌面端才动父层
        canvas.parentElement.style.pointerEvents = want ? 'auto' : 'none';
    }
}
```

手机端关掉 canvas 自身就够了——触摸会穿透到父层 `.canvas-wrap`，摇杆照样收到；
桌面端两层要一起开，鼠标事件才落得到 canvas 上。全项目现在只有这一处写
`.canvas-wrap` 的 `pointer-events`。

**顺带修掉半屏被吃**：摇杆 `touchstart` 里的 `e.preventDefault()` 会连带掐掉浏览器
合成的那一次 `mousedown`，而节点地图正是靠 `mousedown` 选点的——左半屏那一下被摇杆
吃掉了。现在选路 / 选属性 / 商店期间摇杆根本不接管触摸：

```js
if (!G.mobileMode || G.drawerOpen || G.selectingActive) return;
```

### 2. 教程重排：五块石板 + 3 秒节奏

顺序改成 **移动方式 → 图腾生成 → 密文版 → 敌人 → 核心**（v9.25 是 移动 → 子弹
护盾精华 → 密文板 → 闭环图腾 → 精英虚灵终极技）。两处非平凡的决定：

- **闭环图腾提到密文版前面**。判环只看轨迹本身（`checkTrailLoop`），没填任何牌时
  `turType` 默认 `'basic'`——「画个圈就出一座塔」本来就不需要先学密文版。塔先落地，
  第 3 座石板再讲「填什么效果板就出什么类型的塔」，因果顺序反而比原来顺。
- **「敌人」与「核心」拆成两块**。属性三选一与节点地图都挂在 `G.floor % 5 === 0` 上，
  而收尾字幕必须等玩家在节点地图上选完路才播（`selectNode()` 里置的 `outroPending`）
  ——**教程至少要走到第 5 层，收尾才有入口**。所以第 4 块讲怪、第 5 块讲核心，
  正好接在第 5 层那次选路上。

| 石板 | 层 | 步数 | 讲什么 |
|:--|--:|--:|:--|
| 移动方式 | 1 | 7 | WASD、轨迹掉血、Shift 冲刺、轨迹减速、清层 |
| 图腾生成 | 2 | 7 | 画圈出塔、大中小环、火里会烧、怪先打更近的那个 |
| 密文版 | 3 | 12 | 触发板/效果板、填槽、宣读、轮椅组合、P 批量宣读 |
| 敌人 | 4 | 12 | 子弹优先级、快/奶/盾/灼烧/虚灵/精英、分裂、BOSS 专属词条 |
| 核心 | 5 | 10 | 核心 HP、护盾、精华、终极技、围剿、难度公式、每 5 层三选一 |

**字幕节奏压到 3 秒 ±1 秒。** 调度器里两条提示的间隔 = `上一条.hold + 下一条.d`
（`advance()` 重置 `pendTimer`，`triggered()` 比较 `pendTimer >= s.d`），所以只要把
这两个数配对：

```
3 秒 = 180 帧，±1 秒 = ±60 帧   →   hold + d 必须落在 [120, 240]
长句取上限（hold 180 + d 40 = 220），短句取下限（hold 150 + d 0 = 150）
```

29 个间隔全部落在这条带子里，均值 197.2 帧（3.29 秒）。探针逐层逐条核对，不是抽查。
另外没有一条 `hold > 180`——字幕最长停 3 秒，不会压住下一步。

### 测试

`web/probe-9x.mjs` 新增第 16d 节（五块石板的标题与顺序、图腾生成排在密文版之前、

没有一条 hold > 180**、节点地图的 banner 不再硬编码「-5」）与第 19t 节（手机端
`setCanvasPointer` 不碰 `.canvas-wrap`、桌面端两层一起动、端到端「选完节点后父层仍是
`auto`」、全项目只有一处写 `.canvas-wrap` 的 `pointer-events`、摇杆监听里的三态守卫）。
第 19t 节按 `HAS_V926` 分支只在 9.26 上跑——9.25 及更早还没有这个统一入口。

**357 项全绿**（9.25 交叉验证 339 项仍全绿、9.24 247 项全绿、9.23 维持原有的 10 项预期失败）。

那个手机端报障本机复现不出来，所以这次在 headless Chrome 里手搭了一遍真实路径：

## v9.25 — BOSS 专属词条 + 圈层落点化 + 手机端输入修复

**文件**：`密文轨迹demo9.25.html`（构建产物，源码在 `src/9x/`）
**基于**：v9.24

v9.24 首次上线手机端后暴露了 3 个手机端问题 + 3 个 BOSS 设计问题，加上后来追加的
4 条平衡/交互修正与 2 条二次修正，一共十二项。

### 1. 8 个「干扰类」词条改成 BOSS 专属

v9.24 新增的 8 条改变的是**玩家的走法**，挂在随时刷新的小怪身上只是零散骚扰，
玩家记不住也躲不掉。现在词条池分成两组（`AFFIXES` 加 `bossOnly: true`）：

| 组 | 条数 | 谁抽 |
|:--|:--|:--|
| 精英词缀（`regen` / `thorns` / `swift` / `giant` / `vampiric` / `explosive`） | 6 | 精英怪 |
| BOSS 专属（削减/减速/火焰/突进/牵引/封印/群生/敌图腾） | 8 | 只有 BOSS |

`pickAffixes` 从位置参数换成对象（`{ exclude, bossOnly }`），`bossOnly` 取
`true` / `false` / `'any'` 三态。BOSS 仍然排除 🌀突进与 👥群生，所以实际从 14 个里
抽 12 个。顺带把 `spawnDebugMonster()` 里那份内联的抽池逻辑删掉——它是唯一绕开
`pickAffixes` 的地方，最容易在改抽池时漏掉。

### 2. 圈层从「贴身」改成「落点」

原来三个区域词条（削减/减速/火焰）的圈一直贴在自己脚下，而 BOSS 是
`alwaysMoving` 追着玩家跑的——等于「靠近 BOSS 就被永久削弱」，既不可躲也不好看。
现在圈是**扔出去的**：

```
每 300 帧（5s）在 BOSS 周围 [r×1.2, 300px] 的随机位置落一个圈
半径 = 表里的基数 × AFFIX_ZONE_R_MUL(1.5)   削减 100→150、减速 90→135、火焰 90→135
存活 360 帧（6s），同属性同屏最多 3 个
```

落点下界取 `r × 1.2` 就是「不许落在自己脚下」，否则又退回 v9.24 那个样子。
判定主体从「遍历怪读怪身上的 zone」换成遍历 `G.affixZones`——**圈与怪解绑了**，
怪死了圈还在，圈到点自己消失。🌪牵引仍然是贴身拉力，不做圈。

🔥火焰区从「脚下留一条 16px 火轨迹」改成「落一个 135px 的火圈」，所以那套
`spawnAffixFire()` 一并删除。火圈是大而可见、能走出去的东西，不能照抄火轨迹的
`0.8/帧`（站满 6 秒掉 288 血，等于秒杀），定专用常量：

```
FIRE_ZONE_TICK = 6 / FIRE_ZONE_DMG_PER_TICK = 1   ≈ 0.167/帧
穿过（约 0.5 秒）掉 ~5 点；从头站到尾 6 秒掉 60 点——能动就得动，但走得出去
```

扣护盾优先、护盾空了打核心，走和「怪撞核心」同一套结算；同时按 v9.23 的
`FIRE_TURRET_DMG_PER_FRAME × FIRE_ZONE_TICK` 烧玩家图腾——「火焰烧塔」这条
既定规则不该因为火换了形状就失效。

### 3. 圈层同样作用于玩家图腾

玩家只要把塔造在圈外就完全免疫，「圈」对塔阵流派就是一行看不见的数值。现在
判定函数 `getAffixZoneMul(kind, field, entity)` 多了实体参数，图腾也吃圈：

| 圈 | 对玩家 | 对图腾 |
|:--|:--|:--|
| 🟥 削减圈 | 子弹伤害 ×0.6 | 单发伤害 ×0.6 |
| 🟦 减速圈 | 移速 ×0.65 | 出手速度 ×0.65（塔不会移动，移速的等价物就是出手快慢） |
| 🔥 火焰圈 | 持续掉血 | 持续灼烧（v9.23 就有） |

### 4. 图腾攻击力上限 = 玩家攻击力 × 1.0（按旧比例分配）

原来图腾单发伤害写死在类型表里（30/18/50/10/35）再乘层数难度 `(1 + D × 0.3)`，
玩家攻击涨上去之后图腾就相对变弱，两套数值各走各的。现在只有一条关系：

```
TURRET_ATK_CEILING = 1.0
TURRET_RATIO_NORM  = 50 × 1.5 = 75          // 旧 d×m 的最大值（大环闪电）

图腾单发 = getPlayerAttackPower() × 1.0 × (d × m) / 75 × 圈层系数
```

`d` 变成**相对权重**（还在类型表里，但不再是绝对伤害），`m` 是大中小环的尺寸倍率
（0.6 / 1.0 / 1.5）。归一化到最大值之后，「大环闪电」正好顶到 1.0 倍上限，
其余类型与尺寸按旧比例在它下面排开——**比例的相对关系与 v9.24 之前完全一致，
只是绝对值不再随层数难度指数膨胀**：

| 塔 | d × m | 单发（占玩家攻击力） |
|:--|--:|--:|
| 中环基础 🗼 | 30 | 0.40 |
| 大环基础 🗼 | 45 | 0.60 |
| 中环速射 🎯 | 18 | 0.24 |
| 中环闪电 ⚡ | 50 | 0.667 |
| 大环闪电 ⚡ | 75 | **1.00**（上限） |
| 中环冰霜 ❄️ | 10 | 0.133 |
| 中环足迹 🐾 | 35 | 0.467 |

> 上限在 v9.25 开发过程中从 0.6 上调到 1.0——0.6 那一版塔的输出压得太狠，
> 花 6 张牌换来的建筑打不过玩家自己平A。**比例分配没动**，只是整体抬高了 2/3。

`getPlayerAttackPower()`（`04-trail.js`）是子弹与图腾共用的基准威力函数，
`getTurretAttackPower(t)` 在它之上套比例。**在开火那一刻算**而不是召唤时的快照——
所以买完属性成长塔跟着变强。

**怪物的敌对建筑（🗿 敌图腾）单独算**：它的伤害是 `3 + f × 0.2`，不吃玩家攻击力。
玩家的塔会随玩家成长而变强，敌人的塔只随层数变强——这条区分是有意的。

### 5. 玩家开火频率 +20%

`PLAYER_FIRE_RATE_MUL = 1.2`，`p.shootCooldown = Math.max(24, 48 - floor×0.32) / 1.2`。
地板与上限一起缩——只改上面那个 48 的话，后期会被 `Math.max(24, …)` 的地板吃掉，
看着改了其实没生效。

### 6. 「消除」从触发板改成技能

T13 从 `TRIGGERS` 里整个删掉，改成**按 R 触发、30 秒冷却**的固定技能
（手机端是右下角 🧹 圆钮）。效果不变：全场怪各吃 3 倍「怪物反噬」伤害，然后拆掉
场上最早的一座图腾。

理由：它原本的代价只是「烧掉两张牌」，但抽到与否完全看运气，而这个效果的量级
（清场 + 拆塔）足以决定一波团战的胜负——挂在随机掉落上等于把玩家的节奏交给抽卡。
`tryEliminate()` 负责冷却与局面守卫（死亡 / 暂停 / 选卡中都不生效），
冷却中按下会给一句「还要 N.Ns」的反馈而不是静默忽略。

### 7. BOSS 前期数值减压

### 8. BOSS 词条横幅

BOSS 带了什么词条此前只能从它身上的色环猜，战斗中读不出来。现在 `spawnBoss()` 往

### 10. 手机端三处修复

- **🔴 摇杆完全失效（「一进游戏就不动」）**：`touchstart` 原来挂在 `#gameCanvas`
  上，但横屏时 canvas 是 `780:560` 等比缩放 + `max-height:100%`，在比 780:560
  宽得多的手机屏上**只占中间一块**，左右各留一条黑边；铺满全屏的 `.canvas-wrap`
  反倒没有任何监听。拇指的自然落点（屏幕左下角、黑边）根本收不到事件。
  再加上底座被写死在画面内的 `(95, 455)`，即使按在画面里也得先对准那个固定点。
  现在：监听挂 `.canvas-wrap`、判定改成屏幕坐标的左半屏、**底座在按下那一刻
  就地生成**（拖动时底座不动、只动旋钮），视觉从 canvas 绘制换成 DOM
  （`.joy` / `.joy-knob`，要能画在 canvas 之外的黑边上）。
  `JOYSTICK.x/.y` 与 `canvasPointFromTouch()` 一并删除。
- **死亡后无法重开**：`↺ 重开` 在 `.panel` 里，而手机端 `.panel` 是
  `translateX(-100%)` 的收起抽屉，战斗界面上没有任何可点的重开入口。新增
  `#gameoverRestart`（战斗界面正中，150×52），只在 `G.gameOver` 时亮起。
  显示/隐藏只在状态真的翻转时动 DOM：`gameLoop()` 里
  `if (G._gameOverUIShown !== G.gameOver) { … syncGameOverUI(); }`——这一处就覆盖了
  `G.gameOver` 的三个写入点与 `resetGame()` 的复位。
- **没有全屏引导**：`requestFullscreen()` 必须由用户手势触发，原来只在顶栏放了个
  `⛶` 小按钮，玩家注意不到。新增 `#fsOverlay`（盖在职业选择之上，`z-index 300`），
  点一下进全屏、**无论成功与否**都摘掉这一层（iOS Safari 不支持时也要能降级进去玩）。
  `active` 只在启动代码里加一次、`resetGame()` 全程不碰，「只弹一次」是结构自带的。

### 11. 密文版新增三个来源

手牌此前只有四个口子：清层奖励、BOSS 击杀掉落、商人、休整。现在补上三个
「玩着玩着就来了」的来源，全部走既有的**平衡掉落**（`dropBalancedCard()`：
触发板 / 效果板按手牌里少的那一边抽）：

| 来源 | 触发 | 给多少 |
|:--|:--|:--|
| 开局补给 | 正式开局选完职业 | 随机 **6** 张（`START_CARDS`） |
| 击杀奖励 | 每累计击杀 **20** 只 | **30%** 得 1 张（`KILL_CARD_CHANCE`） |
| BOSS 磨血 | 每磨掉 BOSS **25%** 血量 | 50% / 20% / 20% / 10% → **1 / 2 / 3 / 4** 张 |

三处接口决策：

- **一帧一次的连发**。多张一起发时逐张调 `dropBalancedCard()` 会把 `setFeedback`
  与 `updateUI` 也做 n 遍（屏幕上刷 n 行、手牌重绘 n 次）。所以它拆出 `silent`
  参数，连发时静默取牌，由 `grantCards(n, reason)` 统一结算一次。
  **不传参的老调用点行为完全不变**——清层奖励、商人、BOSS 掉落都不用改。
- **“获得几张” 必须画在屏幕上**。用画布的 `showNotification('📥 密文版 ×N')`，
  不是右侧面板的 `setFeedback`——手机端面板是收起的抽屉，战斗时根本看不见
  （和 §8 的 BOSS 横幅是同一个理由）。
- **BOSS 的第 4 道坎（100% = 击杀）不结算**。击杀本身另有一份掉落
  （2~3 张 + 遗物 + 精华），再来一次就是同一件事双发。所以一只 BOSS 从生到死
  只结算 25% / 50% / 75% 三次，`m._cardMilestone` 记在怪自己身上。
  一帧跨两道坎（重击、消除）会**补发两次**，不漏。

判定用**每帧轮询**而不是在各掉血点埋钩子：BOSS 掉血来源太多（玩家子弹、轨迹、
图腾、闪电链、消除、火圈、连带伤害……），逐个埋钩子必漏。代价只是每帧读一次
`hp / maxHp`。轮询放在怪物循环**之后**，所以这一帧被打死的 BOSS 已经被移出数组，
天然不会越界。

开局 6 张的判定读 `Tutorial.seen`：教程是独立沙盒，`cfg.hand` 会预设手牌，
白送 6 张会把教学节奏冲掉（而且教程结束时 `restartRunAfterTutorial()` 会整体重来）。
`seen` 只在这一局的教程真正结束/被跳过后才立起来，所以「重选职业 → 发牌」正好
只发生在正式开局那一次。

### 12. 图腾攻击力上限 0.6 → 1.0

见 §4。只有 `TURRET_ATK_CEILING` 一个常量变了，`d×m/75` 的比例分配没动。

### 13. 手机端「只看得到职业标题」：两个修复 + 一个自检

上线后收到一条报障：手机端开局**只看到「🧙 选择你的密文法师」这一行字，
既没有全屏引导、也没有职业卡**。桌面 Chrome、iPhone UA 的 headless Chrome、
DevTools 设备模拟（844×390）全都复现不出来，所以没有继续猜，做了三件事：

**① 点掉全屏引导的那一下会顺手把职业也选了（真 bug，已修）。**
职业遮罩的标题是**静态 HTML**（`body.html` 里就写着 `active`），卡片却是
`initClassSelection()` 现填的。而 `#fsOverlay` 盖在它上面、整层可点——
点掉它之后，**同一次点按**还会再派发一次合成事件（`touchend → mousedown → click`），
落点正是引导层原本所在的位置，**也就是屏幕正中，而职业卡也正好排在屏幕正中**。
不挡住的话，「点一下进入全屏」=「顺手选中一个职业」，玩家根本没机会选。
修法：摘掉引导层时给 `body` 挂 400ms 的 `.fs-dismissing`，
CSS 把 `.class-card` 的 `pointer-events` 关掉，让那次合成事件落到遮罩上而不是卡片上。

**② 手机端初始化整块裹上 try/catch。**
全屏引导、摇杆视觉、转屏补量这些都是**增强项**，任何一项在某个具体机型上炸了，
都不该把后面的 `initClassSelection()` 一起带走——那正是「只有标题、没有卡」的样子。

**③ 页面底部加一条启动自检条（`#bootErrorBar` + `<head>` 里的 `__bootError`）。**
装在主脚本**之前**，所以能抓到主脚本自己抛的异常；只在启动期报、只报一次
（`window.__booted` 在 `gameLoop()` 之后立起来，进游戏后的运行时报错与它无关）。
另外 `initClassSelection()` 末尾就地断言一次「`CLASSES.length` 个职业有没有
真的落到 DOM 里」——标题是静态的、卡片不是，所以「只看到标题」这件事本身
就是「这一段没跑成」的证据，报出来比让玩家对着一片空白干瞪眼强。


### 1. 判环改看「当前存留的轨迹」

旧的 `checkTrailLoop()`（9.12 起）判的是**玩家走过的路径**——每 3 帧往 `_path` 里塞一个玩家坐标，

## v9.16 — 拆成多文件源码 + 拼装脚本（行为零变化）

**文件**：`密文轨迹demo9.16.html`（构建产物）
**基于**：v9.15

### 为什么

单文件 5573 行、246 KB，继续往上堆改动越来越难维护。先评估过换引擎（Godot），实测后否决：

| 场上怪物 | update+draw | 占 16.67ms 帧预算 |
|:--|:--|:--|
| 50 | 1.82 ms | 11% |
| 500 | 3.33 ms | 20% |
| 1000 | 5.61 ms | 34% |
| 2000 | 15.03 ms | 90% ← 撞墙 |

而 `getMonsterCount()` 把每层怪物**硬钳在 50**——性能墙在游戏自身上限的 10–40 倍处，运行时根本不是瓶颈。
真正的痛点是**维护 5500 行文本**，那是「拆文件」该解决的问题，不是「换引擎」。
换 Godot 还会丢掉三样东西：双击即玩、单文件版本规则、Pages 静态部署（Godot 4 的 Web 导出是 10–30 MB WASM）。

- 作用域与拆分前完全一致，不需要 import/export，**不必改动任何变量引用**
- 避开 `file://` 下 `type="module"` 的 CORS 限制——产物仍然双击可玩

```

  body.html             121 行

  js/
    00-data.js          402 行  词条/怪物/词缀/命运/连杀/关卡/轮椅/职业/遗物/商人/地形
    01-state.js         187 行  G 初始化 + 辅助 + 浮动数值 + 词缀通知 + DOM
    02-combat.js        496 行  被动/得分/怪物生成/分裂/BOSS/治疗
    03-tutorial.js      913 行  TUTORIAL_FLOORS + Tutorial + 教程渲染
    04-trail.js         289 行  核心游戏逻辑/判环/终极技能/组合密文

    06-render.js        571 行  蜿蜒地图 + 渲染
    07-ui.js            667 行  UI/商人/遗物/地图/职业/密文/属性提升/命运
```

分节边界直接沿用文件里原有的 `// ----------` 标记，不重新划界。

### 构建

## v9.15 — 修掉「后期数值爆炸、没意思」

**文件**：`密文轨迹demo9.15.html`
**基于**：v9.14

### 问题：难度早就不起作用了，分数却还在按难度指数乘下去

有一局打到了 118 层，得分 2.37e14，难度读数 ×34,800,440——听起来像后期，玩起来却是静止的：
玩家攻击力从第 10 层起就卡在 260，怪物也一直一样，剩下的 80 层是同一场仗重播。

反查代码，问题不在「难度涨太快」，而在**三个封顶和一个只增不减的计数器**：

| 位置 | 问题 |
|:--|:--|
| 怪物血量 `Math.min(hp, 10000)` | 普通怪 `(36+16)×难度` 在**第 37 层撞顶**，之后每层怪一模一样 |
| 怪物攻击 `× Math.min(diff, 4.0)` | **第 10 层就冻结**。护盾 100 点，一辈子挨的都是 24 点一下 |
| 计分 `scoreValue = 基础分 × diff` | 唯独这个没钳，分数照旧每层 ×1.16 |
| `comboCount` 在 `addScore()` 里自增 | 数的是**加分事件次数**（子弹命中、每帧跳分、炮台全都算），不是击杀，且整局不清零 |
| `killStreak` 只增不减 | 驱动 `addScore(killStreak×2)` |
| 玩家 `Math.min(atkUp+3, 250)` / `轨迹 Math.min(trailDmg+1, 100)` | 玩家 DPS 恒定，配合怪物血量封顶，才有了 118 层 |

实测（同一无头驱动、同为 65 次击杀）：9.14 的 `comboCount` = **611**（只增），`maxCombo` = 611；
9.15 的最长连杀 = 18。`scoreMultiplier = 1+⌊combo/10⌋×0.5` 在 8089 次击杀时是 **×405**——
分数爆炸的真正乘数在这里。

### 改动

**1. 分数改全程对数显示，保留两位小数**

```js
// v9.15: 分数走对数显示——后期分数跨十几个数量级，印原数没人看得懂
function fmtScore(n) {
    if (!(n > 0)) return 'lg 0.00';
    return 'lg ' + Math.log10(n).toFixed(2);
}
```
替换全部 6 处显示点（HUD、结算、对局记录头、终局行、下载文件名）。导出的 JSON 里 `score`
**保留原始数值**（模拟分析要用），另加 `scoreLog: "lg 14.37"` 供人读。

**2. 整个倍率系统删掉**

`comboCount` / `scoreMultiplier` 两个字段及所有读写全部移除，得分就是得分。
原本依赖 `comboCount` 的三处改由**真正会断的** `G.killStreak` 顶替：画布 HUD、连杀爆发阈值、结算「最高连杀」。

并把 `killStreak` 修成真正的「连续击杀」：**3 秒没有击杀、或核心挨打就断**，断了爆发阈值一起复位
（此前一局只能触发一次）。击杀统一走 `registerKill()` 入口。

25 连杀冲击波原本扣 `8 × 难度`——旧曲线下难度涨到几百万，这一下等于无条件清场；加拐点后又几乎无感。
改为按怪物自身血量扣 25%，与 100 连杀的「全怪 -30%」同一套写法，任何楼层都说得通。

**3. 难度曲线加拐点**

```js
const DIFF_KNEE = 30, DIFF_TAIL = 1.6;
function getDifficultyMultiplier() {
    const f = G.floor;
    return Math.pow(1.16, Math.min(f, DIFF_KNEE) - 1)
         * Math.pow(Math.max(1, f / DIFF_KNEE), DIFF_TAIL);
}
```
30 层前与旧曲线**逐值相同**，之后转多项式——仍然一直变难，但不再是天文数字：

| 楼层 | 旧 | 新 |
|:--|:--|:--|
| 30 | ×76.5 | ×76.5（不变） |
| 60 | ×6,353 | ×243 |
| 118 | ×34,800,440 | **×662** |

BOSS 血量同法加拐点，且在第 10/20/30 层与原公式保持完全一致。

**4. 解开怪物上限，让难度真的生效**

- 怪物血量上限 `10000` → `1e9`（防溢出）
- 怪物攻击 `Math.min(diff, 4.0)` → `Math.min(diff^0.35, 12)`：随楼层缓涨，不再第 10 层冻结
- BOSS 血量上限 `1,200,000` → `1e8`；BOSS 攻击同法改 `diff^0.35` 上限 12
- 顺带修 BOSS 血条印的是**未钳的 hp**、与真实血量不符的问题
- 速度 `Math.min(diff, 3.0)` 与 `Math.min(atk, 120)` **不动**——速度必须有上限，否则不可玩

**5. 玩家成长别再撞墙**

攻击力上限 `250` → `2000`，轨迹伤害上限 `100` → `400`。
此前是「攻击力封顶 → 玩 DPS 恒定 → 靠怪物血量封顶维持平衡」，两个封顶互相抵消，才有了 118 层。

**6. 文案同步**：教程字幕的难度公式补上 30 层拐点；典籍里错的

只能干等 25s 超时换直白说法、再 20s 强制放行，整整 45 秒对着空地发呆。

新增 `unreachable(s)`：场上没怪、也没有待生成的怪、且没有 BOSS 待出场时，
需要打怪才能拿到的步骤直接放行（`tick()` 里排在 `triggered()` 之后）。
判定是**白名单式**的——只有标了 `needsMob` 的步骤，以及 `kill`/`essence` 两类触发才算数；
「按 Q」「画闭环」这类玩家自己就能做到的事件即使场上没怪也必须老实等，不能替他跳过。
第 2 层的 `hit`/`pickup`、第 4 层的 `enclosure`/`scorcher` 标了 `needsMob`。

实测：第 2 层「怪物撞核心」这一步的等待从 ~3000 帧降到 541 帧。

### 教程改为「边介绍怪边出怪」
此前每层的怪在 `startFloor` 就一次性放完，讲「💨 疾速怪登场」时疾速怪可能早被打死了，
字幕和场上对不上。现在步骤可以自带 `spawn`：

```js
{ on: 'after', d: 120, spawn: [{ type: 'fast', n: 2 }], hold: 330,
  text: '💨 疾速怪登场：跑得快但很脆，优先清掉它们。' }
```

讲到这里才把怪推进 `Tutorial.spawnQueue` 与 `G.monstersToSpawn`，并把 `G.spawnTimer` 归零让它立刻出场。
配套两处防漏：

- `pendingScript()`：本层还有挂着 `spawn` 的后续步骤时，绝不判定「清空」——
  否则属性三选一会提前弹出，后面的怪反倒出不来
- 层清空分支改为 `if (Tutorial.holdFloor() || Tutorial.pendingScript())`

各层开场只放「普通怪」打底，疾速/治疗/重装/灼烧/精英/虚灵各自挂在自己的介绍步骤上。

实测（无头驱动跑完 1-5 层）：`premature: []`（三选一从未抢跑），
疾速、治疗、重装、灼烧、精英、虚灵六种怪均在对应字幕那一帧出现在场上。

### 教程改为「边介绍怪边出怪」
此前每波的怪在 `startWave` 就一次性放完，讲「💨 疾速怪登场」时疾速怪可能早被打死了，
字幕和场上对不上。现在步骤可以自带 `spawn`（`{ type, n, elite }`）：

```js
{ on: 'after', d: 120, spawn: [{ type: 'fast', n: 2 }], hold: 330,
  text: '💨 疾速怪登场：跑得快但很脆，优先清掉它们。' }
```

讲到这里才把怪推进 `Tutorial.spawnQueue` 与 `G.monstersToSpawn`，并把 `G.spawnTimer` 归零让它立刻出场。

- `pendingScript()`：本波还有挂着 `spawn` 的后续步骤时，绝不判定「清空」——
  否则三选一会提前弹出，后面的怪反倒出不来

各波开场只放「普通怪」打底，疾速/治疗/重装/分裂/迟缓/精英各自挂在自己的介绍步骤上。

## v2.19 — 修复教程只播第一课

**文件**：`密文轨迹demo2.19.html`
**基于**：v2.18

### Bug 修复：新手教程只播完第 1 波就结束
`Tutorial.tick()` 在某一波脚本的步骤播完后无条件调用 `finish()`，而 `finish()` 会立即置 `seen = true`。
第 1 波清空后还要经过「三选一 + 5 秒整顿期」才 `advanceWave()`，这段空档足够 `tick()` 把教程收尾——
于是第 2-5 波的 `startWave()` 判定 `!Tutorial.seen` 失败，整段教程只剩第一课。

改为：步骤播完后，若后面还有教程波（`TUTORIAL_WAVES[this.wave + 1]` 存在）就静待 `startWave()` 装载下一课，
只有最后一课才真正 `finish()`。

实测：第 1-5 波 40 个步骤全部按序触发，横幅依次为「古老的石板-1..5」，以「教程结束 · 从这里开始是你的冒险」收尾。
